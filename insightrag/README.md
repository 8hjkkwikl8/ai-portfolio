# InsightRAG

可追溯的中文知识库问答与检索评测。核心链路不依赖第三方库，也不要求 API Key；配置 OpenAI 兼容接口后可选启用在线生成，但生成结果仍必须通过逐句引用校验。

## 解决什么问题

企业知识库问答的风险通常不是“没有答案”，而是答案看起来合理、却无法回放到原文。InsightRAG 把整条链路拆成可检查的四段：

```text
TXT/MD 文档 → 字符偏移分块 → BM25 + 向量检索（哈希 n-gram / 可选神经嵌入） → RRF 融合
            → 抽取式回答 / 可选在线生成 → 逐句引用校验 → 金标评测
```

每个检索结果都携带 `source`、`chunk_id` 和原文 `start/end` 字符区间，`original[start:end]` 可以精确还原证据文本。回答中的引用编号只能来自本次检索结果，不能创造新来源。

## 快速开始

```bash
python -m pip install -r requirements.txt

# 离线演示：导入样例文档、回答三个问题、运行 12 条金标评测
python demo.py --eval-output artifacts/evaluation.json

# 启动 Web UI 与 API
python -m app.api --port 8001
# 打开 http://127.0.0.1:8001
```

离线演示默认使用临时数据库，退出即清理；传入 `--db path/to.db` 可保留。API 首次启动会在空库中导入 `data/sample_docs/`。

## 功能

- **确定性分块**：按 360 字符窗口、60 字符重叠切分，尽量落在中文句末或换行处；不改变原文，只记录坐标。
- **混合检索**：Okapi BM25 负责精确词项，向量通道负责近似匹配，使用 Reciprocal Rank Fusion 融合两路排名。默认向量通道为 256 维特征哈希字符 n-gram；配置 `INSIGHTRAG_EMBEDDING_*` 后可换成 OpenAI 兼容的神经嵌入接口。
- **可插拔嵌入适配器**：神经嵌入按 `index` 重排批次结果并做单位化，拒绝 NaN、布尔值与非数值分量；分块向量按 `(来源, 分块编号)` 缓存，查询只编码一次。未配置时完全离线，不做任何网络请求。
- **可追溯回答**：离线模式从检索证据中抽取摘要句；每条证据保留来源、分块编号与字符区间。
- **逐句引用校验**：在线生成按句过滤，只有带合法引用编号的句子会保留；若过滤后没有任何合法引用，整段回退离线摘要，并在响应中给出警告。
- **金标评测**：Recall@k、MRR、引用编号合法率、平均延迟，支持逐条查看。零引用记为 `null`（展示为 N/A），不按 1.0 计算。
- **来源整体替换**：同一 `source` 再次导入会在单个事务内替换旧文档与分块，避免重复语料。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health` | 服务状态、文档/分块数量、在线模型是否配置 |
| `POST` | `/api/ingest` | 导入 `{source, content, chunk_size?, overlap?}` |
| `POST` | `/api/query` | 提问 `{question, top_k?, online?}`，返回回答、引用与证据 |
| `POST` | `/api/evaluate` | 运行内置金标或传入 `cases`，返回指标与逐条结果 |
| `GET` | `/api/stats` | 文档来源、检索方式与能力说明 |
| `GET` | `/` | 中文 Web UI |

`/api/ingest` 刻意不接收文件路径或 URL，避免把服务器任意文件或远程地址当作语料读取；单篇文档上限 200 万字符，`overlap` 必须小于 `chunk_size`。

## 评测结果

仓库内 `artifacts/evaluation.json` 由 `python demo.py --eval-output artifacts/evaluation.json` 生成，演示集为 3 篇文档、13 个分块、12 条金标问题（每篇文档 4 条，覆盖不同问法与同义改写）：

| 指标 | 值 | 口径 |
| --- | --- | --- |
| Recall@3 | 1.0 | 期望来源是否出现在前 3 条检索结果 |
| MRR | 1.0 | 首个正确来源排名的倒数均值 |
| 引用编号合法率 | 1.0 | 回答中的引用编号是否都指向本次检索结果 |
| 平均延迟 | ≈14 ms | 本机离线检索加回答，随运行环境浮动 |

这些数字只用于验证链路正确性。语料很小、问题由同一批文档构造，不能代表生产知识库的召回效果。

## 在线生成（可选）

```bash
export OPENAI_BASE_URL="https://your-endpoint/v1"
export OPENAI_API_KEY="..."   # 本地兼容服务可留空
export OPENAI_MODEL="your-model"
python -m app.api --port 8001
```

查询请求需要显式传 `"online": true` 才会调用在线生成；未配置地址与模型时绝不会联网。在线响应会附带提示：仅保留带合法引用编号的句子，编号合法不代表语义忠实度已验证。

## 神经嵌入适配器（可选）

```bash
export INSIGHTRAG_EMBEDDING_BASE_URL="https://your-endpoint/v1"   # 需带 /v1 前缀
export INSIGHTRAG_EMBEDDING_MODEL="your-embedding-model"
export INSIGHTRAG_EMBEDDING_API_KEY="..."   # 可留空，回退 OPENAI_API_KEY
python -m app.api --port 8001
```

三项配置缺任意一项即视为未启用，检索继续使用哈希向量。启用后 `/api/stats` 会显示真实的向量器名称与提示语。适配器按 OpenAI `embeddings` 接口组织批量请求，默认每批 64 条，按响应中的 `index` 重排而不是依赖返回顺序；向量统一做 L2 单位化，余弦相似度即点积。

## 设计取舍

**哈希向量默认、神经嵌入可选。** 特征哈希是确定性、零依赖、可离线复现的默认选择，代价是语义泛化弱于神经嵌入；神经嵌入通过环境变量显式开启，未配置时绝不联网。两种方案共用同一个 `Vectorizer` 协议与余弦实现，检索层不感知差异，因此切换嵌入不改变引用与评测逻辑。这里仍不把默认方案叫作“语义检索”。

**字符偏移而不是仅存文本。** 多存 `start/end` 让证据可以精确回放，也让分块策略可替换；代价是重复导入需要按来源整体替换，而不是增量更新。

**引用编号合法率而不是“忠实度”。** 编号合法只证明回答没有伪造来源，不证明句子语义真的被证据支持。要评估忠实度需要人工标注或 LLM judge，本项目刻意不把这两件事混为一谈。

**离线抽取式回答。** 保守、可复现，但表达自然度有限；在线生成是可选增强，且失败时自动回退，不让演示依赖外部服务。

## 测试

```bash
python -m unittest discover -s tests -q
```

25 项测试覆盖：分块坐标可回放、混合检索排序、无证据处理、非法引用过滤、无引用记 N/A、评测指标、API 契约，以及嵌入适配器的请求形状、批次重排、异常数值拒绝与向量缓存。

## 限制

- 仅支持 `.txt` / `.md` 纯文本，不含 PDF、OCR、表格解析。
- 中文分词采用单字 + 二元组，未引入词典或领域词表。
- SQLite 单机存储，未实现增量索引、分布式检索或多租户隔离。
- 在线生成与神经嵌入模式没有纳入离线金标评测；其质量取决于所接模型或服务。
- Web UI 无鉴权，仅适合本机演示。
